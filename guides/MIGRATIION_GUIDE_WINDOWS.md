# Миграция TrueConf Server с Windows на этот Docker-проект

Эта инструкция описывает перенос TrueConf Server, работающего на Windows, на
Linux-хост с этим Docker Compose проектом (`../docker-compose.yml` + `install.sh`).

Перенос построен вокруг дампа базы данных (`pg_dumpall`), который
`../install.sh` умеет автоматически применять при первом запуске — см. блок
"Checking for dump to import" в `install.sh`.

> ⚠️ Версии PostgreSQL и схема базы различаются между релизами TrueConf
> Server. Перед миграцией сверьтесь с release notes / поддержкой TrueConf,
> если версия на Windows сильно старше версии образа, который вы
> разворачиваете (`TC_IMAGE_TAG` в `../.env`). Сам TrueConf Server умеет
> накатывать "schema patches" поверх импортированного дампа при старте
> (см. лог `tcs_db_dump-*.log`), но большой разрыв версий всё равно стоит
> уточнять отдельно.

## 0. Перед началом

- Не трогайте и не выключайте рабочий Windows-сервер, пока новый
  Docker-сервер не будет проверен и подтверждён рабочим. Он остаётся
  "путём отката" на всё время миграции.
- Уточните лицензию TrueConf: лицензионный ключ обычно привязан к ID
  сервера (hardware ID), который при переезде на новую машину/ОС
  изменится. Заранее свяжитесь с поддержкой TrueConf для перевыпуска
  лицензии на новый сервер, чтобы не остаться без активной лицензии
  после миграции.
- Убедитесь, что новый хост умеет поднять Docker/Docker Compose и имеет
  доступ (по сети) к старому Windows-серверу, либо способ скопировать
  файл дампа (USB, SCP, общая папка и т.д.).

## 1. Снять дамп базы данных на Windows-сервере

TrueConf Server на Windows использует встроенный PostgreSQL. Утилиты
`pg_dump`/`pg_dumpall` поставляются вместе с сервером (обычно в каталоге
установки TrueConf Server, подпапка с PostgreSQL, например
`...\TrueConf Server\pgsql\bin\`).

1. Откройте `cmd`/PowerShell от администратора.
2. Перейдите в папку с `pg_dumpall.exe` из поставки TrueConf Server.
3. Снимите полный дамп кластера (именно `pg_dumpall`, а не `pg_dump` —
   `../install.sh` ожидает на вход файл формата `pg_dumpall`):

   ```powershell
   .\pg_dumpall.exe -U postgres -h 127.0.0.1 -p 5432 > C:\tcs_db.dump
   ```

   Логин, хост и порт подставьте свои — посмотреть их можно в
   конфигурации TrueConf Server (обычно локальный PostgreSQL слушает на
   `127.0.0.1:5432`, пользователь `postgres` или `trueconf`).
4. Проверьте, что файл `tcs_db.dump` не пустой и открывается как
   текстовый SQL-дамп.

Если на Windows-сервере есть важные загруженные файлы (аватары, записи
конференций, вложения в чатах), уточните их расположение в документации
TrueConf для вашей версии — дамп базы переносит только данные БД, но не
бинарные файлы на диске. При необходимости перенесите эти каталоги
отдельно вручную после миграции (структура путей на Linux отличается от
Windows, так что прямое копирование файлов, скорее всего, не сработает
"как есть" — дамп БД остаётся основным поддерживаемым способом переноса).

### Как найти папку с аватарами, записями и вложениями на Windows

В этом Docker-проекте `../docker-compose.yml` монтирует **весь** внутренний
каталог `/opt/trueconf/server/var/lib` контейнера в `./data` на хосте —
то есть `data/database`, `data/dump` и т.д. на самом деле являются
подпапками одного и того же дерева `var/lib`. У Windows-сборки TrueConf
Server внутри каталога установки устроено аналогичное дерево `var\lib\...`
— именно его и нужно найти:

1. Откройте `services.msc`, найдите службу TrueConf Server и посмотрите
   её "Путь к исполняемому файлу" — это укажет на каталог установки
   (по умолчанию обычно что-то вроде
   `C:\Program Files\TrueConf Server\`, но мог быть изменён при
   установке).
2. Внутри каталога установки поищите подпапку `var\lib` (например, через
   проводник или `dir /s /b var\lib` из `cmd`, запущенного в каталоге
   установки).
3. Внутри `var\lib` должны быть подпапки, хранящие файловые данные
   (аватары пользователей, записи конференций, вложения чатов, загрузки)
   — их точные имена зависят от версии сервера. Ориентируйтесь на
   названия вроде `store`, `upload`, `content`, `records`, `avatars` —
   и сверяйте с админ-панелью TrueConf Server (разделы "Записи
   конференций" / "Пользователи" там обычно показывают, куда реально
   пишутся файлы).
4. Если в конфигурационных файлах сервера (`*.conf`/`*.ini` в каталоге
   установки) есть явные пути вида `STORE_PATH`, `DATA_PATH`,
   `CONTENT_PATH` и т.п. — доверяйте им больше, чем догадкам по именам
   папок: администратор мог сменить расположение данных при установке.
5. Если самостоятельно определить точный состав `var\lib` на вашей
   версии не получается — уточните в документации TrueConf Server или
   в поддержке, какие директории включает процедура резервного
   копирования для вашей версии ("Backup and Restore").

После того как нашли нужные подпапки — скопируйте каждую из них в
одноимённую подпапку `data/<имя>` на новом сервере (то есть
Windows `...\var\lib\store` → `data/store`, `...\var\lib\upload` →
`data/upload` и т.д.), сохраняя структуру один в один. Делать это нужно
**до** первого запуска `../install.sh` на новом сервере — наравне с
дампом БД из шага 2.

## 2. Скопировать дамп на новый сервер

Перенесите `tcs_db.dump` на машину с этим проектом, в папку
`data/dump/`:

```bash
mkdir -p data/dump
scp user@windows-host:/C:/tcs_db.dump ./data/dump/tcs_db.dump
```

В `data/dump/` должен лежать **ровно один** файл (кроме `.gitkeep`) —
`../install.sh` явно проверяет это и откажется работать, если файлов
несколько.

## 3. Подготовить `../.env` и образ сервера

1. Если ещё не собирали релиз — выполните `../.idea/sh/prepare.sh` (или
   `.idea/sh/release.sh`), чтобы выбрать тег образа `trueconf-server` и
   сохранить его в `images/trueconf.tar` + `TC_IMAGE_TAG` в `.env`.
   Желательно выбрать версию, совместимую с версией на Windows (см.
   предупреждение в начале файла).
2. Проверьте `../.env`:
   - `TC_IMAGE_TAG` — тег образа.
   - `PRIMARY_INTERFACE` — интерфейс/IP, на который будут забинжены
     порты 80/443/4307.
   - `ADMIN_USER` / `ADMIN_PASSWORD` — эти значения применяются **только
     к действительно пустой базе**. Поскольку мы восстанавливаемся из
     дампа, реальные админ-аккаунты придут из дампа Windows-сервера —
     используйте логин/пароль администратора со старого сервера.

## 4. Убедиться, что это "чистая" установка

Проверка в `../install.sh` применяет дамп только если каталога
`data/database` ещё не существует (то есть это свежая установка). Если
вы уже запускали `install.sh` на этом хосте раньше и там есть данные —
очистите их:

```bash
.idea/sh/clear-data.sh
```

⚠️ Это необратимо удалит всё содержимое `../data` на новом сервере. Не
запускайте эту команду, если там уже есть данные, которые нужно
сохранить.

## 5. Запустить установку

```bash
./install.sh
```

Скрипт сам:
- загрузит образ из `../images/trueconf.tar`;
- поднимет `docker-compose up -d`;
- дождётся, пока TrueConf Server на первом старте применит дамп и
  накатит схемные патчи;
- выведет хвост лога импорта дампа и удалит временный файл дампа из
  `data/dump/` после успешного импорта.

Следите за процессом:

```bash
docker logs -f trueconf-server
```

## 6. Проверка после миграции

- Зайдите в веб-интерфейс администратора под учётными данными со
  старого Windows-сервера (не под `ADMIN_USER`/`ADMIN_PASSWORD` из
  `../.env` — см. пункт 3).
- Сверьте список пользователей, групп и адресную книгу с Windows-сервером.
- Проверьте историю конференций/звонков, если она важна.
- Сделайте тестовый звонок/конференцию, чтобы убедиться, что сервис
  полностью работоспособен.
- Только после успешной проверки — выводите старый Windows-сервер из
  эксплуатации.

## Откат

Пока Windows-сервер не выключен и не удалён — откат тривиален: просто
продолжайте использовать его, а Docker-инсталляцию остановите
(`docker-compose down`) и при необходимости пересоберите с нуля после
исправления проблемы (`../.idea/sh/clear-data.sh` → `./install.sh` с новым
дампом).
